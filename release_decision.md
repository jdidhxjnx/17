# Решение о готовности выпуска

## Решение

**ОСТАНОВИТЬ выпуск кандидата `1.5.0-rc1` на текущем наборе доказательств.**

Решение основано на обязательных критериях спецификации, а не на предположении об успехе непроведённых проверок.

## Основания

1. `R_RESTORE` / T04 — `blocked`: цель восстановления недоступна, последнее испытание восстановления в пакете отсутствует. RTO ≤ 20 мин и RPO ≤ 15 мин не подтверждены.
2. `R_PERFORMANCE` / T05 — `not_run`: нет измерения для 20 операторов и 1000 заявок; нельзя подтвердить успех ≥ 99% и p95 ≤ 800 мс.
3. Бинарный файл `app-1.5.0-rc1.zip` не предоставлен — контрольный хеш не вычислен.
4. Руководство 1.4.2 противоречит SPEC-1.0: 5 вложений вместо 3 и небезопасный совет после тайм-аута.

T01, T02, T03 отмечены `passed` в синтетическом пакете, но их маркеры не являются внешними журналами. Статусы сохранены без преувеличения доказательной силы.

## Минимальные условия пересмотра

| Условие | Владелец | Необходимое доказательство |
|---|---|---|
| Предоставить пакет и вычислить хеш | `student_engineer` | Фактический файл и хеш с указанием алгоритма |
| Провести проверку восстановления | `student_engineer` организует среду; `student_tester` фиксирует результат | Протокол восстановления, сверка набора, фактические RTO ≤ 20 мин и RPO ≤ 15 мин |
| Провести нагрузочное измерение | `student_tester` | Результаты для 20 операторов / 1000 заявок; успех ≥ 99%; p95 ≤ 800 мс по `ceil(0.95·n)` |
| Исправить и сверить руководство | Владелец документации/выпуска (в пакете не назван) | Обновлённый текст 1.5.0, сверенный со SPEC-1.0 |

После выполнения этих условий решение можно пересмотреть. Пороги качества не снижаются.
